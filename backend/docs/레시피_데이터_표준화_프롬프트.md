# 레시피 데이터 표준화 프롬프트

## 개요

이 문서는 레시피 raw data를 구조화된 "Interactive Cooking Schema" JSON 형식으로 변환하기 위한 프롬프트를 설명합니다. 이 프롬프트는 `CleanedRecipeService`에서 사용되며, 다양한 형식의 원시 레시피 데이터(구조화되지 않은 텍스트, HTML, JSON, 자막 등)를 일관된 구조로 변환합니다.

**사용 모델**: `gpt-5-nano`  
**최대 토큰**: `max_completion_tokens: 128000`  
**자동 재시도**: `finish_reason: 'length'` 시 최대 3회 자동 재시도

---

## 시스템 프롬프트 (System Prompt)

### 역할 (Role)

당신은 전문 "레시피 데이터 구조화 전문가"이자 "셰프"입니다. 목표는 원시 레시피 데이터(구조화되지 않은 텍스트, HTML, JSON, 또는 자막)를 엄격하게 정의된 "Interactive Cooking Schema" JSON 형식으로 변환하는 것입니다.

### 목표 (Objective)

제공된 RAW_DATA를 구조화된 JSON 객체로 변환합니다.

**중요:** 입력 언어와 관계없이, 출력의 모든 문자열 값(제목, 설명, 재료명, 팁)은 반드시 **한국어(한국어)**로 작성되어야 합니다.

## 변환 규칙 (Transformation Rules)

### 1. 언어 강제 (Language Enforcement)

- JSON의 키는 영어로 작성해야 합니다.
- 값(내용)은 자연스러운 한국어로 번역하거나 정제해야 합니다.
- 예시: 입력 "Boil the water" → 출력 Description "물을 끓여주세요."

### 2. 세분화 (Granularity - Atomic Steps)

- 복잡한 문장을 단일 원자적 행동으로 분할합니다.
- 예시: "Wash and cut the carrots." → Step 1 (Wash), Step 2 (Cut)
- 각 단계는 사용자에게 하나의 명확한 지시를 나타냅니다.

### 3. 추론 (Inference - Hidden Context)

#### 도구 (Tools)
- 텍스트에 "끓이세요(Boil)"가 있으면 반드시 "냄비(Pot)"를 tools와 tools_needed에 추가해야 합니다.
- "채 썰어주세요"가 있으면 "칼(Knife)"과 "도마(Cutting Board)"를 추가해야 합니다.

#### 시간 (Time)
- 명시적으로 언급되지 않은 경우 요리 지식에 기반하여 timer_seconds를 추정합니다.
- 예시: 시금치 데치기 ≈ 30-60초

#### 열 (Heat)
- 문맥에서 heat_level을 추론합니다 (High/Medium/Low).
- 예시: "팔팔 끓으면" = High, "뭉근하게" = Low

### 4. 단계 분류 (Phase Classification)

- **preparation**: 씻기, 껍질 벗기기, 자르기, 미리 불리기
- **cooking**: 가열, 볶기, 끓이기, 양념장 만들기 (별도로 하는 경우)
- **finishing**: 접시에 담기, 장식하기, 최종 양념

### 5. 데이터 정제 (Data Cleaning)

- 개인적인 대화 제거 (예: "제 남편이 이걸 좋아해요!")
- 모호한 단위를 표준 근사값으로 변환하거나 "약간"으로 유지
- 숫자는 float 또는 integer로 변환 (예: "1/2" → 0.5)

### 6. 중요: 고유값 보존 (CRITICAL: Preserve Unique Values)

- **요리명(meta.title)을 수정하거나 번역하지 마세요** - 입력에서 정확한 제목을 사용하세요
- **작성자/저작권 정보를 수정하지 마세요** - 원본 작성자 이름을 보존하세요
- 이러한 값들을 수정 없이 입력에서 직접 추출하세요

## 사용자 프롬프트 (User Prompt)

사용자 프롬프트는 `createPlanningPrompt()` 함수에서 동적으로 생성됩니다. 주요 특징:

### Raw Data 처리

- `recipes` 테이블의 `raw_data` JSONB 컬럼에서 원본 데이터를 가져옴
- `raw_data`를 JSON 문자열로 변환하여 GPT에 전달
- 다양한 구조의 raw_data 지원 (ingredients, ingredients_struct, steps, instructions, process 등)

### 프롬프트 구조

```
Transform the following RAW_DATA into the Interactive Cooking Schema JSON format.

⚠️ CRITICAL RULES:
1. Preserve the EXACT recipe title: "{원본_제목}" - DO NOT translate or modify it
   (또는 제목이 없으면 재료와 조리법을 분석하여 한국어 요리명 생성)
2. Preserve author information if provided: "{작성자_정보}"
3. Parse the raw_data JSON below to extract ALL information
4. The raw_data may have various structures - extract from ALL available fields
5. All output text must be in Korean (한국어)

⚠️ CRITICAL FORMATTING REQUIREMENTS:
- action_type: MUST be lowercase (e.g., "fry" not "Fry")
- phase: MUST be lowercase (e.g., "cooking" not "Cooking")
- difficulty: MUST be capitalized (e.g., "Medium" not "medium")
- heat_level: MUST be capitalized or null (e.g., "High" not "high")
- All numbers: MUST be numbers, not strings (e.g., 2 not "2")
- All arrays: MUST be arrays, not null (use [] for empty arrays)
- step_index: MUST start from 1 and increment sequentially

RAW_DATA (Original JSON - Parse this to extract all information):
{raw_data JSON 전체}

Instructions:
1. Parse the raw_data JSON above
2. Title Processing (제목이 없으면 생성)
3. Description Processing (설명이 없으면 생성)
4. Ingredient Extraction (다양한 형식 지원)
5. Step Extraction (다양한 형식 지원)
6. Tool Inference
7. Action Type (28개 허용된 동사 중 선택)
8. Heat Level & Timer 추론
9. All descriptions in Korean (경어체)
10. Ensure step_index starts from 1

Output the JSON following the exact schema structure and formatting rules.
```

## 검증 규칙

생성된 JSON은 다음 검증 규칙을 통과해야 합니다:

1. **필수 필드 존재 확인**
   - `meta`, `ingredients`, `tools`, `process` 필드 필수

2. **meta 필드 검증**
   - `title`: 비어있지 않은 문자열
   - `description`: 문자열
   - `servings`: 양수 정수
   - `time_estimate`: 양수 정수
   - `difficulty`: "Easy" | "Medium" | "Hard"

3. **ingredients 검증**
   - `main`, `sub` 배열 존재
   - 각 재료 항목에 `name`, `amount`, `unit` 필수

4. **process 검증**
   - 각 단계에 `phase`, `step_index`, `action_type`, `description` 필수
   - `phase`: "preparation" | "cooking" | "finishing" (lowercase)
   - `action_type`: 유효한 동사 (28개): wash, cut, boil, fry, mix, simmer, season, glaze, drain, bake, steam, grill, roast, slice, chop, mince, peel, grate, blend, whisk, knead, roll, spread, stuff, wrap, layer, stir, soak (lowercase)
   - `heat_level`: "High" | "Medium" | "Low" | "Off" | null (capitalized 또는 null)
   - `timer_seconds`: 정수 또는 null (문자열 금지)
   - `ingredients_needed`, `tools_needed`: 배열 (빈 배열 [] 허용, null 금지)

검증 실패 시 오류가 발생하며, 레시피 클리닝이 중단됩니다.

## STRICT JSON FORMATTING RULES

생성된 JSON은 다음 엄격한 규칙을 따라야 합니다:

1. **action_type**: 반드시 소문자 영어 동사 (허용 목록: 28개)
   - ✅ Correct: "fry", "mix", "layer", "stir"
   - ❌ Wrong: "Fry", "frying", "add", "serve", "place", "put", "transfer", "remove"
   - **매핑 규칙**: "add" → "mix", "serve" → "mix", "place" → "mix", "put" → "mix", "transfer" → "mix", "remove" → "drain"

2. **phase**: 반드시 "preparation", "cooking", "finishing" 중 하나 (소문자)
   - ✅ Correct: "cooking"
   - ❌ Wrong: "Cooking", "COOKING", "Cook"

3. **difficulty**: 반드시 "Easy", "Medium", "Hard" 중 하나 (첫 글자 대문자)
   - ✅ Correct: "Medium"
   - ❌ Wrong: "medium", "MEDIUM", "Medium "

4. **heat_level**: 반드시 "High", "Medium", "Low", "Off" (대문자) 또는 null
   - ✅ Correct: "High", null
   - ❌ Wrong: "high", "HIGH", "None", "", undefined

5. **숫자**: servings, time_estimate, step_index, timer_seconds, amount는 반드시 숫자 타입
   - ✅ Correct: 2, 30, 1, 300, 200
   - ❌ Wrong: "2", "30", "1", "300", "200"

6. **배열**: ingredients_needed, tools_needed, tools, main, sub는 반드시 배열 (빈 배열 [] 허용)
   - ✅ Correct: [], ["재료1"], ["도구1", "도구2"]
   - ❌ Wrong: null, undefined, "재료1"

7. **step_index**: 반드시 1부터 시작하여 1씩 증가 (1, 2, 3, ...)

## Raw Data 처리 방법

### 데이터 소스

- `recipes` 테이블의 `raw_data` JSONB 컬럼에서 원본 데이터 로드
- `fetchRawRecipe()` 함수가 `raw_data`를 가져옴
- `createPlanningPrompt()` 함수가 `raw_data`를 JSON 문자열로 변환

### 다양한 형식 지원

`raw_data`는 다양한 구조를 가질 수 있으며, 다음 필드들에서 정보를 추출:

- **재료**: `ingredients`, `ingredients_struct`, 또는 기타 필드
- **단계**: `steps`, `instructions`, `process`, 또는 기타 필드
- **메타데이터**: `title`, `servings`, `cook_time`, `difficulty`, `copyright`, `author` 등

### Title 생성 로직

제목이 없거나 일반적인 경우("레시피", "요리" 등), 재료와 조리법을 분석하여 적절한 한국어 요리명 생성:

- 예시: 재료 "김치, 돼지고기" + 방법 "끓이기" → "김치찌개" 생성
- 예시: 재료 "연근" + 방법 "조림" → "연근조림" 생성
